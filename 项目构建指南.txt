# 电脑防护系统 —— 完整技术方案

---

## 一、方案概述

### 1.1 背景与目标

用户日常默认开启可信 VPN，经常访问非白名单网址、下载未知文件、安装来源不明的软件。目标是：在不干扰正常使用的前提下，防止个人信息被盗取和电脑被病毒感染。

### 1.2 核心设计原则

- **确定性优先**：规则层做决策，LLM 只处理灰区
- **用户可审计**：每条拦截都有完整证据链，用户可自行核实
- **先拦后放**：默认拦截，用户手动放行，控制权交给用户
- **分层防御**：任何单一层被绕过，其他层仍能兜底
- **零日常操作**：一次安装授权，之后完全静默运行

### 1.3 架构总览

## 二、浏览器扩展模块

### 2.1 白名单强制拦截

**拦截逻辑**：使用 `declarativeNetRequest` API，默认拦截所有非白名单域名的请求。白名单精确到"域名 + 路径前缀"，避免整个域名被放行后用户误入恶意跳转页。

**技术约束**：Manifest V3 之后，`webRequestBlocking` 对普通扩展不可用，只有企业策略安装的扩展才能用阻塞式拦截。因此需要使用 `declarativeNetRequest` 做声明式拦截（静态规则上限 30000 条，动态规则上限 5000 条），配合 `webRequest` 非阻塞监听做辅助判断。

**拦截后交互**：弹出告警，展示完整证据链，用户决定是否临时放行。

### 2.2 JS 运行时行为监控

只看跳转太狭隘。完整的运行时检测应覆盖以下维度：

**动态代码执行监控**：Hook `eval()`、`Function()` 构造函数、`setTimeout(string)` 等入口，记录传入的字符串参数，分析是否包含编码后的 payload（如 `eval(atob('...'))`）。参考 **jsdet** 项目，它在沙箱化的 QuickJS-on-WebAssembly 运行时中执行不可信 JS，拦截每一次 API 调用、DOM 变更、网络请求和 `eval()` 执行。

**WebAssembly 模块行为分析**：攻击者将核心恶意逻辑编译为 Wasm 模块，使静态分析几乎失效。参考 **JSWasM** 框架，通过安全参考监视器追踪 JS 与嵌入 Wasm 模块之间的函数调用和属性访问。**JSMBox** 同样在 Chromium 扩展中实现了运行时监控。

**DOM 操作与数据窃取监控**：监控动态创建的表单、隐藏 iframe、向非白名单域名发起的 `fetch`/`XMLHttpRequest` 请求。重点关注表单提交劫持——恶意脚本可能拦截登录信息并转发到攻击者服务器。商业扩展 **Secureye** 已实现检测混淆代码执行（如 `eval(atob())`）、来自未知域名的隐藏 iframe 和跨域数据外发。

**运行时行为评分**：参考 **BSM** 框架，对动态 JS 执行进行行为评分，综合评估危险程度，而非简单"命中即拦截"，大幅降低误报率。

**剪贴板劫持检测**：监控剪贴板内容，检测恶意页面是否替换加密货币地址等敏感信息。

**通知权限滥用检测**：监控网站是否诱导用户授予浏览器通知权限后推送钓鱼链接。

**PWA 伪装检测**：监控恶意网站是否伪装成 PWA 应用，安装后脱离浏览器沙箱运行。

### 2.3 自动跳转拦截

**需要拦截的跳转类型**：

- `meta refresh`：页面加载后自动刷新
- `window.location` 赋值：`location.href`/`assign()`/`replace()`
- `window.open()`：新窗口/标签页打开目标 URL
- 表单自动提交：JS 触发 `form.submit()`
- 伪点击：模拟用户点击隐藏的 `<a>` 标签
- `document.write` 注入 `meta refresh`

**拦截策略**：默认拦截所有自动跳转。在 `document-start` 阶段 hook 原生 API，通过 `event.isTrusted` 区分用户主动触发（`true`）和脚本模拟（`false`）。脚本发起的跳转一律拦截，弹出确认框。参考 **GSecurity AutoNavGuard** 的实现思路。

**跳转目标安全检查流程**：

1. 提取目标 URL
2. 本地白名单检查 → 命中直接放行
3. 云查目标 URL（Google Safe Browsing + URLhaus 并行）
4. 任一来源返回恶意 → 强制拦截，展示完整证据链
5. 均无记录 → 允许手动放行，弹出警示
6. 查询失败 → 默认拦截，提示"无法验证目标网址安全性"

**重定向链追踪**：通过 `chrome.webRequest.onBeforeRedirect` 追踪整个重定向链。`safe-site.com → tracking.com → malware.com` 这种多级跳转，即使每一跳单独看都"安全"，整体也应标记为可疑。链长度超过 3 次触发告警。

**用户手动放行交互**：

```
⚠ 检测到自动跳转

当前页面: example.com
跳转目标: suspicious-site.com/path

安全检查结果:
  Google Safe Browsing: 无记录
  URLhaus: 无记录
  域名注册时间: 3天前 (风险)
  域名相似度: 未发现仿冒

此网址未经威胁情报验证，且域名注册时间很短。
建议不要继续访问。

[仍然访问]  [返回安全页面]
```

放行选项：一次性放行 / 记住此域名（加入白名单，默认关闭）/ 记录决策（后续该 URL 被标记为恶意时主动提醒）。

### 2.4 钓鱼页面内容判断

Google Safe Browsing 和 URLhaus 依赖已知恶意 URL 黑名单，对新注册的钓鱼域名或尚未被收录的恶意页面无能为力。LLM 可分析页面内容（通过 Content Script 提取文本、表单结构、DOM 特征），判断是否存在钓鱼特征：

- 页面是否在模仿知名品牌的登录界面
- 表单提交目标是否与页面声称的身份不一致
- 是否存在紧迫性话术（"您的账户将在 24 小时内被冻结"）
- 页面是否有隐藏 iframe 或跨域数据外发

研究显示 LLM 在钓鱼网站检测上可达 **96% 准确率**，比传统方法更能识别零日钓鱼页面。

## 三、本地后台服务模块

### 3.1 威胁情报聚合查询

**多源并行查询**：

| 数据源 | 说明 | 配额 |
|---|---|---|
| Google Safe Browsing | 免费，检测恶意软件、钓鱼、有害应用 | 10,000 次/天 |
| URLhaus (abuse.ch) | 无需 API Key，专门收集恶意软件分发 URL | 无明确限制 |
| VirusTotal VTAI | 无需 API Key，免费配额内使用 | 配额内 |
| sec-mcp 聚合工具 | 聚合 OpenPhish、PhishTank、PhishStats、URLhaus、BlocklistDE、CINSSCORE | 取决于各源 |

**VirusTotal 免费公共 API 限制**：每分钟 4 次、每天 500 次请求，必须有严格的队列和缓存机制。

**队列设计**：所有云查请求进入优先级队列，高优先级（系统目录新文件、进程可疑）排前面，低优先级（用户目录普通文件）排后面。消费者以固定间隔（默认 20 秒）从队列头部取出执行，天然满足 4 次/分钟限制。

**缓存层**：SQLite 缓存查询结果。文件哈希查询永久缓存（同一哈希结果不变），URL 查询缓存 24 小时。缓存命中直接返回，不消耗 API 配额。

**去重机制**：队列中相同哈希或相同 URL 请求自动合并。

### 3.2 恶意网站证据链展示

每条拦截必须展示完整证据链，包含来源、具体数据、可信度。

**Google Safe Browsing 返回字段**：威胁类型包括 `MALWARE`、`SOCIAL_ENGINEERING`（钓鱼/欺诈）、`UNWANTED_SOFTWARE`、`POTENTIALLY_HARMFUL_APPLICATION`。`FullHashDetail` 包含匹配的 `ThreatType` 和 `ThreatAttribute`。

**URLhaus 返回字段**：`threat`（如 `malware_download`）、`url_status`（`online`/`offline`）、`tags`（如 `elf`、`hajime`）、`date_added`、关联 `payloads` 中的文件哈希和 VirusTotal 检测比率。`query_status` 为 `ok` 表示命中，`no_results` 表示未收录。

**VirusTotal 返回字段**：`positives`（恶意引擎数）、`total`（总引擎数）、`scan_date`，以及每个引擎的具体检测结果 `scans` 对象（`detected`、`result` 如 `Trojan.Generic.3611249`、`version`）。使用 `allinfo` 参数可获取沙箱行为数据（文件操作、网络操作、互斥体/注册表操作）。

**本地检测结果标注**：

| 检测项 | 标注内容 | 示例 |
|---|---|---|
| 双扩展名 | 检测到的两个扩展名 | `.exe 伪装成 .jpg` |
| 高危目录 | 文件所在路径 | `C:\Users\xxx\Downloads\` |
| 高熵值 | 熵值数值和阈值 | `熵值 7.82 (阈值 7.4)，疑似加壳` |
| 签名状态 | 签名有效性和发布者 | `无数字签名` 或 `签名无效: 发布者与文件不匹配` |
| 进程链异常 | 父进程路径 | `父进程: chrome.exe (浏览器不应派生系统进程)` |

**展示原则**：每条证据必须有明确来源、有原始数据（显示 API 返回的关键字段）、有可验证链接（指向威胁情报平台原始记录页）。

**置信度评分**：Safe Browsing 和 URLhaus 明确命中权重最高；VirusTotal 多引擎检测比率按比例计分；本地启发式检测作为辅助证据，权重较低。

### 3.3 文件云查与隔离

**哈希查询优先**：文件下载完成后立即计算 SHA-256，先查询 VirusTotal 哈希库（零上传、快速度）。哈希未知时，可触发文件上传做多引擎扫描。VTAI 本地文件提交上限 32MB，inline 提交上限 24MB。

**隔离区管理**：可疑文件移入 `guard_data/quarantine`，记录原始路径、哈希、隔离时间、原因。支持列表、恢复、彻底删除。

### 3.4 进程创建监控

**ETW 订阅**：通过 `Microsoft-Windows-Kernel-Process` provider 在进程创建瞬间捕获事件，比 WMI 的 `Win32_ProcessStartTrace` 更实时、开销更低。

**新进程快速评估**：

提取进程名、完整路径、命令行参数、父进程 PID、启动时间、数字签名状态。

命中任一即标记可疑：
- 路径位于 `%TEMP%`、`%APPDATA%`、下载目录或用户目录下的隐藏文件夹
- 父进程是浏览器、Office 或脚本宿主（`wscript.exe`/`cscript.exe`/`mshta.exe`）
- 命令行包含编码后的 PowerShell 命令、`certutil -decode`、`bitsadmin /transfer` 等下载执行模式
- 无数字签名，或签名状态为 `UnknownError`/`NotSigned`
- 进程名模仿系统进程（`scvhost.exe` 模仿 `svchost.exe`、`lsasss.exe` 模仿 `lsass.exe`）

命中后触发详细扫描：读取 PE 头、计算文件哈希、查询 VirusTotal、检查导入表是否包含可疑 API（`CreateRemoteThread`、`WriteProcessMemory`、`SetWindowsHookEx`）。

### 3.5 拦截"下载后自动运行"

**方案一：Windows 原生 ASR 规则**（推荐首选）

启用 Microsoft Defender 的**攻击面缩减（ASR）规则**：

- **"阻止 JavaScript 或 VBScript 启动下载的可执行内容"**（Rule ID: D3E037E1-3EB8-44C8-A917-57927947596D）
- **"阻止可执行文件运行，除非它们满足流行度、年龄或受信任列表标准"**

通过注册表静默配置：`HKLM:\SOFTWARE\Policies\Microsoft\Windows Defender\Windows Defender Exploit Guard\ASR\Rules`，值类型 `REG_DWORD`，设为 `1` 启用。

**方案二：进程创建拦截**（更细粒度）

- **用户态 HIPS 方案**：参考 **R3ShieldCore**，通过 DLL 注入所有进程，hook `ntdll`/`user32`/`ws2_32` 等用户态出口，在行为发生前拦截。不需要驱动，兼容性好，但可能被高级恶意软件绕过。
- **内核回调方案**：通过 `PsSetCreateProcessNotifyRoutine` 等内核回调拦截。参考 **iMonitorSDK**，支持 XP 到 Win11。**LotL-Watcher** 使用 WMI/ETW 以内核级精度监控进程创建，支持自动杀死或挂起可疑进程。

**集成到本地服务**：使用 ETW 或 WMI 订阅进程创建事件，检查新进程可执行文件是否位于下载目录，检查父进程是否为浏览器、脚本宿主或压缩软件，命中可疑规则时自动挂起并告警。无需内核驱动，实现成本可控。

### 3.6 文件系统全局监控

**方案选择：USN Journal 优于 ReadDirectoryChangesW**

`ReadDirectoryChangesW` 不支持对卷根目录的递归监控，要覆盖整个磁盘必须为每个子目录单独创建监控句柄，极易漏事件、爆句柄数、卡主线程。系统目录（`System Volume Information`、`$Recycle.Bin`）会被拒绝访问，导致监控盲区。

**NTFS USN Journal** 是 NTFS 文件系统原生的卷级变更日志，每次文件创建、删除、重命名、写入都会生成 USN 记录，实现无遗漏的卷级捕获。

**读取流程**：

```cpp
// 1. 打开卷句柄
HANDLE hVol = CreateFileW(L"\\?\C:", GENERIC_READ|GENERIC_WRITE,
                          FILE_SHARE_READ|FILE_SHARE_WRITE, ...);
// 2. 查询当前日志范围
USN_JOURNAL_DATA ujd;
DeviceIoControl(hVol, FSCTL_QUERY_USN_JOURNAL, ..., &ujd, ...);
// 3. 循环读取增量记录
READ_USN_JOURNAL_DATA rujd = {0};
rujd.StartUsn = last_usn;  // 维护上次读取的 USN 游标
rujd.ReasonMask = USN_REASON_FILE_CREATE | USN_REASON_DATA_EXTEND;
while (running) {
    DWORD bytesReturned;
    DeviceIoControl(hVol, FSCTL_READ_USN_JOURNAL, &rujd, sizeof(rujd),
                    buffer, bufferSize, &bytesReturned, NULL);
    // 解析 buffer 中的 USN_RECORD，提取文件名和变更类型
    // 更新 last_usn 游标
}
```

**轮询间隔**：每 2 秒拉取一次增量记录，批量处理。USN Journal 日志空间有限，长时间不读可能回绕。启动时记录当前 `NextUsn` 作为基线，持续增量读取；若 `last_usn` 落后于 `FirstUsn`（日志回绕），触发全盘文件索引重建。

**"莫名其妙多出来的文件"判定逻辑**：

| 维度 | 判定规则 |
|---|---|
| 位置 | 系统目录中出现非安装程序创建的 `exe`/`dll`/`sys`，风险评分高 |
| 创建者 | 通过 ETW 关联文件创建与进程创建事件，浏览器/脚本宿主创建的文件标记可疑 |
| 时间 | 文件创建时间与用户安装软件时间窗口不匹配，标记可疑 |
| 内容 | 计算 SHA-256，查询 VirusTotal，哈希查询优先于文件上传 |

**资源占用**：每 2 秒拉取增量记录，每次几 KB 到几十 KB，开销可控。使用独立 I/O 线程，避免阻塞主线程。

### 3.7 内存占用监控

**轮询机制**：使用 `psutil` 库，`virtual_memory().percent` 获取系统内存使用率。

```python
import psutil, threading

class MemoryMonitor(threading.Thread):
    def __init__(self, threshold=80.0, interval=30.0, on_alert=None):
        super().__init__(daemon=True)
        self.threshold = threshold
        self.interval = interval
        self.on_alert = on_alert
        self._stop = threading.Event()

    def run(self):
        while not self._stop.wait(self.interval):
            mem = psutil.virtual_memory()
            if mem.percent >= self.threshold:
                self.on_alert(mem)
```

**30 秒间隔的取舍**：Windows 没有内存占用的系统级信号，只能轮询。30 秒足以捕捉持续性异常，但可能漏掉瞬时 spike。触发阈值后可临时提高轮询频率（5 秒一次），持续 2 分钟确认是持续性还是瞬时异常。

**超阈值后的全面扫描**：

第一层（资源维度）：按内存占用排序 Top 20 进程，计算 `memory_percent` 和 `cpu_percent`。重点关注内存高但 CPU 几乎为零（静默等待的窃密进程），或 CPU 与内存双高（挖矿/加密勒索）。

第二层（可信度维度）：检查数字签名、发布者、文件路径。无签名、无版本信息、公司名伪装成微软但签名无效的进程风险最高。

第三层（行为维度）：检查网络连接、打开的文件句柄、加载的模块。重点关注连接非白名单 IP/域名、加载异常 DLL、在系统目录外创建临时文件。

第四层（父子关系维度）：检查父子链是否合理。异常特征包括父进程已退出但子进程仍在运行、`svchost.exe` 父进程不是 `services.exe`、浏览器进程派生 `cmd.exe` 或 `powershell.exe`。

### 3.8 游戏场景的误报排除

**核心思路**：从"绝对阈值触发"转向"相对基线 + 行为特征"复合判断。

**判断维度**：

| 维度 | 正常高内存特征 | 异常高内存特征 |
|---|---|---|
| 数字签名 | 有效签名，知名厂商 | 无签名、签名无效、发布者伪装 |
| 安装路径 | `Program Files`、Steam 库目录 | `%TEMP%`、`%APPDATA%`、下载目录 |
| 父进程链 | Steam/Epic/启动器派生 | 浏览器、Office、脚本宿主派生 |
| 前台状态 | 当前全屏、用户正在交互 | 后台运行，无可见窗口 |
| 内存曲线 | 启动后上升，稳定在平台期 | 持续线性增长，或周期性剧烈波动 |
| 进程年龄 | 与用户启动游戏时间吻合 | 启动时间与用户操作无关 |
| 网络行为 | 连接游戏服务器、更新 CDN | 连接非白名单 IP，或大量外发数据 |

**前台交互感知**：通过 `GetForegroundWindow()` + `GetWindowThreadProcessId()` 拿到前台窗口进程 PID。如果该 PID 同时满足全屏/最大化、有效签名、正规安装目录、高内存占用，判定为"用户正在主动使用的高内存应用"，进入静默模式（阈值临时上调至 92% 或暂停触发全面扫描，只保留轻量记录）。静默模式设置超时（4 小时），避免恶意进程伪造全屏窗口永久逃避监控。

**基线学习机制**：首次检测到进程内存超 70% 时，记录特征进入观察期（10 分钟）。观察期内内存稳定在区间（如 6-8 GB 波动，不持续增长），加入基线库，后续高内存不再触发全面扫描，只做周期性轻量校验。内存持续线性增长（每小时增长 500MB 且无上限）则不加入，恢复正常监控。基线库持久化存储（SQLite），每次进程启动重新校验关键特征。

**内存曲线分析**：维护每个高内存进程最近 N 次采样值，计算斜率（线性回归）、波动方差、峰值出现时间。斜率持续为正且无收敛趋势的进程，即使当前占用不高，也应标记可疑。

**游戏特有场景**：反作弊进程（EasyAntiCheat、BattlEye、Vanguard）有明确签名，加入可信列表，但需监控其驱动加载行为。游戏启动器（Steam、Epic）以启动器为根节点构建进程树，整棵树走轻量验证。无签名游戏模组降低告警级别，由用户确认。

**豁免安全边界**：豁免不等于不监控（保留签名校验、路径校验、网络连接记录），豁免有超时（4 小时），豁免不继承（子进程需单独验证），豁免可撤销（用户可查看和撤销）。

### 3.9 用户白名单

**定位**：降噪完全交给用户白名单，LLM 不参与降噪。

**粒度**：默认用哈希 + 签名组合。用户点击"信任"时，记录当前文件哈希和签名信息。文件被修改（哈希变化）或签名失效时，白名单自动失效。

**失效机制**：文件哈希变化、签名失效或被吊销、文件路径非预期变化、条目超过一定时间未使用（可选）时自动撤销。

**优先级**：用户白名单优先级高于 LLM，但低于确定性恶意规则。第一层已明确判定为恶意（哈希在黑名单），即使用户加了白名单也应拦截并提示。

**安全防护**：加入白名单时，如有任何确定性恶意特征，弹出强警告要求二次确认。白名单条目定期回溯校验（重新检查哈希、签名、威胁情报），发现已标记为恶意自动撤销并告警。白名单条目数量上限（500 条）。

### 3.10 LLM 末端裁决

**定位**：只处理规则和白名单都裁决不了的灰区案例，不是降噪工具，不是第一道防线。

**灰区定义**：

- 规则命中但置信度低（正则匹配可疑字符串但上下文可能合法）
- 多信号冲突（签名有效但行为异常、路径在系统目录但创建者不是安装程序）
- 静态分析无法裁决（混淆脚本、页面可疑但 Safe Browsing 和 URLhaus 均无记录）
- 用户主动请求（点击"分析这个"）

**不适合 LLM 的**：哈希明确在黑名单（直接拦截）、签名明确有效且路径正常（直接放行）、用户已加白名单（直接放行）、纯确定性查询（哈希查询、签名校验）。

**输出方式**：LLM 给出判断和理由后，不直接执行动作，而是给出建议操作，等待用户确认。用户确认后，选择加入白名单或执行处置。

**架构**：规则层做决策，LLM 层做解释和补充。本地模型优先（如 Qwen2.5-1.5B、Phi-3-mini 跑在 CPU 上），云端 API 兜底。事件驱动调用，不做轮询。脱敏后发送（替换用户名、IP、文件路径敏感部分）。

**值得 LLM 做的**：告警聚合降噪（多条弱信号合成可读判断）、混淆脚本分析（Base64 解码后分析实际意图）、钓鱼页面判断、误报申诉处理、自然语言日志查询。

**LLM 成本**：GPT-4o-mini 或 Claude Haiku 级别单次分析约 1000-2000 token，成本 0.001-0.01 美元。每天 50 次，月成本 1.5-15 美元。

## 四、安装与自启动

### 4.1 组件执行级别

| 组件 | 执行级别 | 说明 |
|---|---|---|
| 安装程序 | `requireAdministrator` | 写注册表策略，仅运行一次 |
| 本地服务 exe | `asInvoker` | 开机自启，普通用户权限 |
| 浏览器扩展 | — | 通过策略静默安装 |

### 4.2 开机自启动

**方式一（主方式）**：将本地服务快捷方式放入 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`，用户登录时自动运行，无需管理员权限。

**方式二（备选）**：向 `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` 写入字符串值，指向 exe 路径。写 `HKEY_CURRENT_USER` 只需当前用户权限。

exe 打包加 `--noconsole` 参数，避免开机弹出黑窗口。

### 4.3 浏览器扩展静默安装

通过 Chrome 企业策略 **`ExtensionInstallForcelist`**，将扩展 ID 和更新源 URL 写入注册表：

```
HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Google\Chrome\ExtensionInstallForcelist
```

策略值格式：`扩展ID;更新源URL`。写入后扩展静默安装，用户无法卸载或停用。企业策略语义下，扩展所需权限自动授予，无需用户确认。

Edge 对应路径：`HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\Edge\ExtensionInstallForcelist`。

安装完成后验证：Chrome 地址栏输入 `chrome://policy`，查看 `ExtensionInstallForcelist` 是否显示 OK。

### 4.4 PyInstaller 打包

```bash
# 本地服务 exe
pyinstaller --onefile --noconsole --name Guardian guardian.py

# 安装程序 exe
pyinstaller --onefile --noconsole --uac-admin --name GuardianSetup setup.py
```

`--uac-admin` 使 exe 清单嵌入 `requireAdministrator`，Windows 启动时自动弹出 UAC 对话框。

### 4.5 安装流程（用户视角）

```
用户双击 GuardianSetup.exe
        ↓
Windows 弹出 UAC 对话框 → 用户点击"是"
        ↓
安装程序自动执行：
  1. 复制 Guardian.exe 到 %LOCALAPPDATA%\Guardian\
  2. 将快捷方式写入启动文件夹
  3. 写入 HKCU Run 注册表键
  4. 写入 Chrome/Edge 的 ExtensionInstallForcelist 策略
  5. 立即启动 Guardian.exe
        ↓
用户重启电脑 → Guardian 自动运行，扩展自动加载
```

## 五、完整事件处理流程

```
事件触发（进程创建 / 文件变更 / 内存超阈值 / 浏览器拦截 / 自动跳转）
        ↓
第一层：确定性规则
    ├── 明确恶意 → 拦截 + 告警（结束）
    ├── 明确无害 → 放行（结束）
    └── 灰区 → 进入第二层
        ↓
第二层：用户白名单
    ├── 命中且特征一致 → 放行（结束）
    ├── 命中但特征变化 → 撤销白名单，进入第三层
    └── 未命中 → 进入第三层
        ↓
第三层：LLM 末端裁决
    ├── 生成判断 + 理由 + 建议
    ├── 推送给用户
    └── 用户确认
        ├── 信任 → 加入白名单（回到第二层）
        └── 不信任 → 执行处置
```

## 六、已知局限与应对

### 6.1 EDR 层面盲区

**系统调用间接执行**绕过用户态 hook，**ETW 绕过**使遥测失效，**内核回调脱钩**规避检测。MITRE ATT&CK 评估显示顶级攻击团队能在 **500ms 内**完成从初始执行到 EDR 遥测盲区的转移。

**BYOVD（自带易受攻击驱动）** ：攻击者利用微软签名的但有漏洞的驱动关闭端点防护。Windows 自带 `BTR.sys` 驱动也可被滥用。

**应对**：多信号交叉验证（浏览器扩展行为评分、本地服务文件哈希云查、ASR 规则执行拦截相互印证），驱动加载监控（BYOVD 典型特征是加载签名合法但不在正常驱动列表中的驱动），定期完整性校验（对自身可执行文件、配置文件、注册表项做哈希校验）。

### 6.2 防护软件被"合法"关闭

Windows 检测到另一个安全解决方案活跃时会自动关闭 Defender。恶意软件可注册假杀毒产品，让 Windows 自动关闭 Defender。攻击者还可滥用 `wmic`、`sc`、`PowerShell` 禁用安全软件。

**应对**：本地服务监控自身注册表项、启动项和进程状态，被篡改或终止时立即恢复并记录。

### 6.3 VPN 常开的影响

VPN 加密隧道包裹所有流量，本地 DNS 过滤失效、网关层内容检测失效、基于 IP 的威胁情报匹配失效。威胁情报查询由本地服务直接发起，数据经 VPN 隧道传输，不受影响。如需 DNS 层过滤，必须配置 **Split Tunneling（拆分隧道）** ，将 DNS 查询流量排除在 VPN 隧道之外。

### 6.4 杀软误报

写注册表策略 + 静默安装扩展 + 开机自启的组合行为可能被 Windows Defender 或第三方杀软标记。建议对 exe 进行数字签名，或引导用户将安装目录加入白名单。

### 6.5 HTTPS 解密

**不建议**在用户设备上做全局 HTTPS 中间人解密。需要安装根证书，引入新的安全风险，且可能被带证书固定的应用拒绝。浏览器扩展的 Content Script 能在不解密流量的情况下监控页面内 JS 行为，是更优解。

## 七、功能优先级建议

| 优先级 | 功能 | 理由 |
|---|---|---|
| P0 | 白名单拦截 + Safe Browsing 查询 + 文件哈希云查 | 最小可用链路，跑通后再扩展 |

| P2 | USN Journal 文件监控 + 内存监控 | 补全系统完整性检测维度 |
| P2 | JS 行为检测扩展（动态代码执行、Wasm 分析） | 需要逐步迭代 |
| P3 | LLM 末端裁决 | 灰区处理，成本可控后引入 |
| P3 | 自我保护机制（完整性校验、防卸载） | 长期投入方向，初期简单校验起步 |

根据你的技术方案，我梳理了各个模块可借鉴的开源项目，并按功能模块分类：

### 🖥️ 端点安全 / EDR 平台
* **Velociraptor**：基于 Go 的端点监控与数字取证平台，支持实时监控、文件系统访问和进程活动追踪，可作为架构参考。
* **Radegast EDR**：轻量级 EDR 平台，使用 FastAPI + SQLAlchemy 构建，内置 SQLite 免部署，适合家庭或个人场景，支持日志端到端加密。
* **OpenEDR**：功能完整的 EDR，包含进程监控、文件系统微过滤、注册表监控、网络过滤等组件，其 DLL 注入和 API Hook 机制可直接借鉴。
* **endpoint-security-ai-agent**：开源 AI EDR，具备实时威胁检测、自动隔离恶意文件、ChatGPT 风格 AI 分析助手和 Web 仪表盘，架构与你的方案高度相似。

### 🛡️ HIPS / 主动防御
* **Bulwark (磐垒)**：C++/Qt 实现的 Windows HIPS，核心思路是**监控敏感行为 → 规则引擎决策 → 灰区弹窗让用户裁决**，三层架构（内核态驱动 R0、用户态服务 R3、Qt UI）与你方案的分层理念一致。
* **LLM HIPS**：将本地大模型接入 Windows 内核拦截链路的进程威胁分析系统，**内核层做拦截决策，LLM 做分析解释，两者完全解耦**——内核回调微秒级返回，不等待 LLM 推理。
* **OSSEC**：老牌开源 HIDS，支持日志分析、文件完整性检查、Windows 注册表监控、实时告警和主动响应，策略引擎设计值得参考。

### 🌐 浏览器扩展
* **Osprey**：开源浏览器安全扩展，通过 **20+ 威胁情报提供商**检查每个网站，支持钓鱼页面、恶意网站、诈骗和新注册域名检测，隐私优先设计（URL 检查通过代理路由隐藏 IP）。
* **SmuggleShield**：专门防御 HTML 走私攻击的浏览器扩展，检测常见 HTML 走私模式，Chrome 和 Firefox 兼容，可直接借鉴其检测规则。
* **PrivyDeck Personal Shield**：开源浏览器扩展，支持广告、追踪器和恶意软件拦截，带可选账户同步。

### 📡 威胁情报聚合
* **vamp-darkweb-intel**：威胁情报 CLI，**无需 API Key** 即可并行查询 ThreatFox、URLhaus、MalwareBazaar、GreyNoise、Shodan InternetDB 等免费源，支持**关联引擎**——当 ≥2 个独立来源标记同一指标时自动提升严重等级。
* **Threat Intelligence Hub**：基于 Flask + Vue 的威胁情报聚合平台，整合多源威胁情报，支持 IP/URL/哈希查询和 WAF 协同自动拦截。
* **MISP**：开源威胁情报平台，支持 IOC 共享和标准化格式，可作为威胁情报数据存储和交换的参考。

### ⚙️ 进程监控 (ETW)
* **ETWProcessMon2**：基于 ETW 监控进程/线程/内存/镜像加载/TCPIP，支持**远程线程注入检测**和通过 VirtualMemAlloc 事件进行内存 Payload 检测。
* **pyetwkit**：高性能 Python ETW 消费库，Rust 后端驱动，支持多会话同时运行和基于 Manifest 的类型化事件，如果你的本地服务用 Python 编写，这个库可以直接集成。
* **system_monitor**：Rust 实现的 Windows 内核事件监控工具，基于 ETW，定位为 Procmon 的替代品，提供更多事件和有用过滤器。

### 📂 文件系统监控 (USN Journal)
* **UsnParser**：C# 实现的命令行工具，可读取和监控 NTFS/ReFS 的 USN Change Journal，核心 USN 读取逻辑可直接参考。
* **change-journal**：Rust 库，提供统一的变更日志 API，**Windows 上使用 USN Journal，Linux 上使用 fanotify**，适合跨平台场景。
* **USN-Journal-Parser**：Python 脚本，解析 NTFS USN Change Journal，如果你用 Python 开发本地服务，这是最直接的参考。

### 🤖 LLM 安全分析
* **BlueGuardian AI**：多 AI 模型（Claude、GPT-4、Gemini、Ollama）驱动的蓝队安全分析框架，包含**多模型共识系统**防止 AI 幻觉，支持恶意软件、文档、钓鱼、内存、网络等多种分析代理，以及 Docker 沙箱安全执行。
* **malwar**：专为 agentic AI 技能文件设计的静态分析引擎，流程为 **SKILL.md → 规则引擎 → URL 爬虫 → LLM 分析器 → 威胁情报 → 裁决**，其 LLM 分析器专门检测正则表达式无法发现的**社会工程、隐藏意图和上下文依赖攻击**。
